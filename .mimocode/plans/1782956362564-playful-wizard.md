# Plan: LiveKit Signal Connection Fix + n8n SMTP

## Problem 1: LiveKit "could not establish signal connection"

### Root Cause
`LIVEKIT_PUBLIC_URL=wss://staging.meeting-automation.com` → Browser verbindet über nginx-ingress → Ingress routet `/rtc` und `/twirp` an `backend:8000` statt an `livekit-server-staging:7880`.

Backend Logs: `WebSocket /rtc/v1?access_token=... 403` — Backend kann LiveKit WebSocket nicht handlen.

### Fix
Ingress `meeting-staging` ändern:
- `/rtc` → `livekit-server-staging:7880` (statt `backend:8000`)
- `/twirp` → `livekit-server-staging:7880` (statt `backend:8000`)

**Datei**: K8s Ingress Ressource (nicht im Repo, nur in K8s)

**Änderung**:
```yaml
- path: /rtc
  pathType: Prefix
  backend:
    service:
      name: livekit-server-staging  # war: backend
      port:
        number: 7880                 # war: 8000
- path: /twirp
  pathType: Prefix
  backend:
    service:
      name: livekit-server-staging  # war: backend
      port:
        number: 7880                 # war: 8000
```

### Verifikation
1. `kubectl get ingress meeting-staging -o yaml` → `/rtc` → `livekit-server-staging:7880`
2. Meeting erstellen → LiveKit Token mit `wss://staging.meeting-automation.com`
3. Browser → `wss://staging.meeting-automation.com/rtc` → LiveKit Server → Connection OK
4. Kein "could not establish signal connection" mehr
