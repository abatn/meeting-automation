# Phase 90: Celery Worker Memory — 4Gi beibehalten

## Entscheidung
Celery Worker bleibt bei **4Gi** Memory Limit.

## Begründung
- Sentinel LLM (~1.5GB) wird nur bei PRO/ENTREPRISE Recordings geladen
- Staging hat 3 ENTREPRISE-Tenants (System Management, SMARTIST, Default Client)
- Aktuell 0 aktive Recordings → Sentinel nicht geladen (992Mi Verbrauch)
- **Production-Readiness**: Jeder Tenant bekommt eigenen Server mit 4 Workern
- 4 Workers × (300MB Python + 120MB ONNX) = 1.68GB Baseline
- + Sentinel Spike: 1.5GB → Peak ~3.2GB → 4Gi nötig
- Reduktion auf 2Gi/3Gi wäre ein Risiko bei parallelen Sentinel-Tasks

## Keine Änderungen erforderlich
- Status quo beibehalten
- Einsparung von Phase 89 (5.2Gi) bleibt erhalten
