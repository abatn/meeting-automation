# Phase 120: ArgoCD sicher aktivieren (2026-07-02)

## Warum hat ArgoCD das letzte Mal die Pipeline zerstört?
- Git-YAMLs hatten alte Image-Tags (`latest`, `staging`) die nicht im k3s existieren
- Git-YAML hatte `hostNetwork: true` auf Egress (falsch)
- Git-YAML hatte `ws://localhost:7880` statt `ws://livekit-server-staging:7880`
- ArgoCD `selfHeal=true` hat ALLE manuellen Fixes auf den Git-Zustand zurückgesetzt

## Lösung: Git-YAMLs zuerst an aktuelle Cluster-State anpassen

### Schritt 1: Image-Tags in Git-YAMLs pinnen

| Datei | Aktuell (Git) | Korrekt (Cluster) |
|-------|---------------|-------------------|
| `backend-deployment.yaml` | `meeting-automation-backend:latest` | `meeting-automation-backend:v20260701230046` |
| `celery-worker-deployment.yaml` | `meeting-automation-backend:latest` | `meeting-automation-backend:v20260701230046` |
| `celery-beat-deployment.yaml` | `meeting-automation-backend:latest` | `meeting-automation-backend:v20260701230046` |
| `frontend-deployment.yaml` | `meeting-automation-frontend:staging` | `meeting-automation-frontend:v20260701214740` |
| `minio-statefulset.yaml` | `RELEASE.2025-09-07` | `RELEASE.2024-12-18` (aktuelle Version) |

### Schritt 2: Egress-YAML fixen (bereits im Working Tree)
- `hostNetwork: true` → entfernt
- `LIVEKIT_WS_URL` → `ws://livekit-server-staging:7880`
- `hostPort: 7000` → entfernt

### Schritt 3: Git commit + push
```bash
git add -A
git commit -m "fix: pin image tags, fix egress config for ArgoCD safety"
git push origin main
```

### Schritt 4: ArgoCD Application mit Sicherheits-Settings erstellen
```yaml
syncPolicy:
  automated:
    prune: false      # Keine Auto-Delete
    selfHeal: false   # Kein Auto-Revert
  syncOptions:
    - ServerSideApply=true
```

### Schritt 5: Erst nach `argocd app diff` syncen

## Verifikation
1. `argocd app diff` → 0 oder minimale Changes
2. `argocd app sync` → alle Pods bleiben Running
3. Egress: `service ready` + WS_URL korrekt
4. Backend Login: HTTP 200
5. `kubectl get pods` → 0 Broken
