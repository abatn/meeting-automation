# Phase 92: Zweite Node + CloudNativePG + Velero

## Ziel
Zweite k3s Node hinzufügen für echtes HA (PostgreSQL Replikation, Velero Cluster-Backups)

## Voraussetzungen
- OCI VM mit Oracle Linux 9.7 ARM64 (gleiche Spec wie Node 1)
- k3s v1.35.5+k3s1 (gleiche Version)
- Netzwerkzugang zu Node 1 (10.0.0.191)
- Join-Token von Node 1

## Schritte

### 1. OCI VM erstellen
- ARM64, Oracle Linux 9.7, 4 OCPUs, 24GB RAM
- Gleiche Security List wie Node 1
- Internal IP: 10.0.0.192 (z.B.)

### 2. k3s Agent auf Node 2 installieren
```bash
# Auf Node 1: Join-Token holen
k3s token create --print-join-command

# Auf Node 2: k3s Agent installieren
curl -sfL https://get.k3s.io | K3S_URL=https://10.0.0.191:6443 K3S_TOKEN=<token> sh -s - agent
```

### 3. Longhorn auf 2 Nodes
- `default-replica-count: 2` (statt 1)
- Longhorn repliziert automatisch über 2 Nodes
- Volume wird automatisch auf Node 2 repliziert

### 4. CloudNativePG installieren
- Operator: `cnpg/cloudnative-pg`
- Cluster: 2 Repliken (1 pro Node)
- Backup: Barman → MinIO

### 5. Velero installieren
- Backup-Storage: MinIO (bereits im Cluster)
- Volume-Snapshots: Longhorn (CSI)
- Tägliche Backups

## Risiken
- OCI Kosten: 2. VM (~$30/Monat)
- Netzwerk: 2. VM muss im gleichen VCN sein
- k3s Join: Token-Ablauf (24h)
