# ISO 27001 Compliance for Meeting Automation System

This document outlines the measures and practices implemented in the Meeting Automation System to ensure compliance with ISO 27001 standards, focusing on information security management.

## 1. Information Security Management System (ISMS)

The system adopts a risk-based approach to information security, establishing controls to protect the confidentiality, integrity, and availability of information assets.

## 2. Key Security Controls Implemented

### 2.1. Security Policy (A.5)

- **A.5.1.1 Policies for Information Security**: Defined in `docs/ISO27001.md` and `docs/SECURITY.md` (if applicable).
- **A.5.1.2 Review of the Policies for Information Security**: Policies are reviewed annually or upon significant changes.

### 2.2. Organization of Information Security (A.6)

- **A.6.1.1 Information Security Roles and Responsibilities**: Roles are clearly defined, with security responsibilities assigned to relevant personnel.
- **A.6.2.1 Mobile Device Policy**: (To be defined based on deployment environment)
- **A.6.2.2 Teleworking**: (To be defined based on deployment environment)

### 2.3. Human Resource Security (A.7)

- **A.7.2.1 Background Checks**: (To be defined as part of HR processes)
- **A.7.2.2 Security Awareness, Education and Training**: Ongoing training for developers and users on security best practices.

### 2.4. Asset Management (A.8)

- **A.8.1.1 Inventory of Assets**: All system components (servers, databases, applications, code repositories) are identified and documented.
- **A.8.2.1 Information Classification**: Data handled by the system is classified (e.g., public, internal, confidential) and protected accordingly.
- **A.8.2.2 Labelling of Information**: (To be implemented as per data handling procedures)

### 2.5. Access Control (A.9)

- **A.9.2.1 User Registration and De-registration**: Formal processes for creating and removing user access.
- **A.9.2.3 Management of Privileged Access Rights**: Least privilege principle applied; privileged access is restricted and monitored.
- **A.9.2.4 Management of Secret Authentication Information of Users**: Passwords are hashed, and MFA secrets are encrypted.
- **A.9.4.1 Access Control Policy**: Implemented through role-based access control (RBAC) in the backend.
    - **Update (März 2026)**: Implementierung einer Redis-basierten Token-Blacklist. Bei einem Benutzer-Logout wird der Access Token serverseitig in Redis gespeichert und sofort ungültig gemacht, um Replay-Angriffe zu verhindern und eine sofortige Zugriffsaufhebung gemäß ISO 27001 zu gewährleisten.
- **A.9.4.4 Use of Privileged Utility Programs**: Restricted and logged.
- **A.9.4.5 Access Control to Program Source Code**: Access to GitHub repositories is restricted.

### 2.6. Cryptography (A.10)

- **A.10.1.1 Policy on the Use of Cryptographic Controls**: Encryption used for sensitive data at rest and in transit.
- **A.10.1.2 Key Management**: Encryption keys are securely generated, stored (e.g., environment variables, secret management systems), and rotated.

### 2.7. Physical and Environmental Security (A.11)

- (To be defined based on physical infrastructure and cloud provider security measures)

### 2.8. Operations Security (A.12)

- **A.12.1.1 Documented Operating Procedures**: Deployment and operational procedures are documented.
- **A.12.4.1 Logging of Events**: Comprehensive audit logging of user actions and system events (`backend/app/middleware/audit_middleware.py`).
    - **Härtung (Feb 2026)**: Die Middleware validiert nun aktiv die Benutzeridentität (`user_id`) gegen die Datenbank, bevor Log-Einträge erstellt werden. Dies verhindert Foreign-Key-Fehler durch veraltete JWT-Tokens nach Datenbank-Resets. Stale oder anonyme Sessions werden sicher als Metadaten (`stale_user_id`) erfasst, um die Rückverfolgbarkeit zu gewährleisten, ohne die DB-Integrität zu gefährden.
- **A.12.4.2 Protection of Log Information**: Logs are protected from tampering and unauthorized access.
- **A.12.6.1 Management of Technical Vulnerabilities**: Regular vulnerability scanning (Trivy in CI/CD) and patch management.
- **A.12.7.1 Control of Software Installation on Operational Systems**: Only authorized software is installed.

### 2.9. Communications Security (A.13)

- **A.13.1.1 Network Security Management**: Network segmentation, firewalls, and secure configurations for inter-service communication.
- **A.13.1.3 Segregation in Networks**: Backend, frontend, databases, and AI services are segregated in distinct networks/subnets.
- **A.13.2.1 Information Transfer Policies and Procedures**: Secure protocols (HTTPS, SSH) for data transfer.

### 2.10. System Acquisition, Development and Maintenance (A.14)

- **A.14.2.8 System Security Testing**: Includes unit, integration, and API tests, as well as vulnerability assessments.
- **A.14.2.9 System Acceptance Testing**: Security requirements are part of acceptance criteria.
